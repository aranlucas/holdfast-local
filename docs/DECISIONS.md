# Research and decisions

Research checked 2 October 2026; live merchant policies are precedents for design, never built-in eligibility rules.

- **Per-product terms and explicit start date.** [Best Buy’s primary policy](https://www.bestbuy.com/site/help-topics/return-exchange-policy/pcmcat260800050014.c?id=pcmcat260800050014) describes periods starting when the product is received and different seller/product cases. This supports asking users for the applicable item-specific rule and purchase/delivery start. Holdfast uses only fictional sample merchants and user-entered terms.
- **Original evidence, local transactions.** [MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) documents structured records/Blobs, same-origin storage and browser eviction. IndexedDB keeps original file bytes alongside facts, with transaction-based backup restore. Backups remain explicit because browser storage is not a durable encrypted vault.
- **Offline first-use parsing.** [MDN service-worker guidance](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) describes installation, asset caching and lifecycle. The build generates a versioned precache including the lazy PDF.js chunk and local worker. Offline PDF import is tested before the PDF reader has ever been opened.
- **Local document parsing.** [Mozilla PDF.js](https://github.com/mozilla/pdf.js) is the official implementation used via `pdfjs-dist` from the npm registry. Only the text layer is read; no external OCR, LLM or model endpoint. Textless documents remain evidence with manual inputs.
- **Trust boundary.** Extraction evidence shows exact matched lines with qualitative labels; it is always followed by three human confirmations. Unknown policies produce unknown dates. Source labels are plain text, not loaded URLs. React escapes field text, and proof HTML explicitly escapes every user-supplied string. File names are sanitized.
- **Calendar arithmetic.** Receipts contain calendar dates, not UTC instants. Arithmetic uses whole UTC calendar days to avoid DST shifts, while display fixes UTC so receipt dates retain their entered day. “Today” is the browser’s local day; it refreshes on focus/visibility and once a minute. Month additions clamp to month end. Day-count convention and final-day uncertainty remain visible.
- **Proof before action.** A packet is an organized archive, not a submitted claim. Checklist progress measures preparation, not likelihood of a successful return. No contact, notification subscription, legal decision, paid service or public release was implemented.

- **Multi-item receipts without duplicated totals.** Conservative labeled or priced lines are suggestions, with original line numbers. Users choose products, then independently verify each record. No duration, confirmation or entire receipt total is copied between products. The original document is retained with every selected record; taxes/shipping/discount allocation stays manual. The verification queue is ephemeral, with explicit cancellation wording and persistence only after each confirmation.
- **Calendar interoperability without a service.** [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) defines date-valued events, exclusive end dates, CRLF line endings, text escaping and 75-octet folding. Holdfast exports fixed all-day dates with stable event identifiers, UTF-8-safe folding, no embedded alarms/subscriptions, and minimal context. Unknown/unconfirmed rules do not become events. The [ICAL.js primary repository](https://github.com/kewisch/ical.js) supplies an independent development-only parser for round-trip verification. Clients may add their own default alerts; importing is a one-time copy, not synchronization.

Next useful experiments: optional encrypted cabinet; offline printable packet with document thumbnails; user research on line-item tax/discount attribution; real Safari/Firefox and calendar-client import checks. These should preserve per-item rules and human confirmation. No external OCR or AI provider is needed for the current product.
